# Mood review and query shortcuts

From **Record Data → Mood History**, review today's, the last seven days', or the last thirty days' check-ins. Choose **Day** to browse any older date using the arrows or by tapping the full date. The next-day arrow stops at today. Search notes without leaving the history or tap an entry to edit it. Pull to refresh; returning from an edit also refreshes the list.

On a past selected day, **+** starts a missed check-in at the first valid instant of that local day and prompts you to choose its approximate time in the editor. Today and recent-period views retain the editor's automatic current-time default, including full precision. Opening an existing check-in retains its timestamp and original scale. Selecting a day does not create or change any data.

The summary follows the selected period and note search. It counts check-ins and local calendar days, and averages each rating's position on its original scale. For example, 2 on a 0–4 scale and 75 on a 0–100 scale average to 62.5%. This is descriptive, per-check-in information, not a clinical score. Invalid or missing scales are excluded from the average and disclosed in the footer. Entries retain their original ratings and scales. Period boundaries follow the device calendar, including daylight-saving changes. Filtering, sorting, displayed dates and recorded-day counts use stored instants in the current calendar and time zone. Midnight belongs to exactly one day. A failed load clears the previous rows and reports that history is unavailable; it never presents stale data as an empty selected day.

The shared timestamp picker preserves full precision for **Now**, **Last**, and unchanged initial values. Wheel edits and minute/hour/day/month adjustments clear seconds and fractions. The explicit **Seconds** adjustment preserves seconds but clears fractional seconds. Date-only choices use the start of the day. Date/time attribute and range pickers also clear seconds/fractions for manual date/time choices. Automatic capture and import timestamps retain their precision. Mood creation now respects the supplied timestamp, and the mood editor stores the original rating scale on new check-ins.

These precision rules deliberately make estimated event times recognizable for data-accuracy analysis and potential forgetfulness proxies. See [Timestamp precision, accuracy estimates and forgetfulness proxies](timestamp-precision.md) for the complete rules, date-only exceptions, existing activity set-at metadata and limits of that inference.

In **Explore → Query → Load**, search saved-query names and data types using case/accent-insensitive, whitespace-separated terms. Every term must match. Swipe right and tap **Run** to execute without changing your draft; tap a row to open it for editing. Direct Run is only available for ordinary exploration, not when selecting a query for a graph. Rename/delete actions continue to apply to the visible filtered row.

Manual UI checks should cover Day navigation and date selection, Add/Edit in Mood History, filter changes and note search, each timestamp shortcut, and opening/running/renaming a filtered saved query.
